# ReDash 下一代多模态控制面：最终架构方案规范

> **定位**：对标 **Orca** 与 **T3 Code** 的工业级最佳实践，摒弃脆弱臃肿的重型 P2P 协议，打造**“局域网真直连 + 公网 E2EE 盲中继 + 极客 Tailscale 穿透”**的全终端零信任现代运维架构。

---

## 一、架构定型与核心设计哲学

经过对主流开源方案（`stablyai/orca`、`pingdotgg/t3code`）的深度调研与技术论证，我们确立了以下核心共识：

1. **终端与运维流量本质极轻**：终端 PTY 字符、遥测指标与治理指令单次仅几百字节至几 KB，文本流根本不会打爆服务器带宽。为了省这点流量强行引入 WebRTC（庞大的 ICE/STUN/TURN 状态机与手机切后台秒断问题）是**严重的过度设计（Over-engineering）**。
2. **中心化的真正威胁在于“明文窥视”，而非“流量转发”**：用户最担心的是 Hub 服务器部署在公网被黑客攻破后窃听所有节点的 Shell、命令与凭据。**解决的核心是端到端加密（E2EE），将 Hub 彻底降级为无法解密的“盲管道（Dumb Pipe）”**。
3. **局域网与公网场景严格分流**：同 Wi-Fi/同机房走本地直通（0 公网流量、<1ms 延迟）；跨公网走 E2EE 盲中继；需要公网物理直连的高级用户直接无缝叠加 Tailscale / WireGuard。

## 三、三端（Web / 移动端 / 桌面端）统一规范

| 终端类型 | 局域网模式 (Local Path) | 公网模式 (Public Path) | 核心优势 |
|---|---|---|---|
| **Web 网页端**<br>(无需安装任何客户端) | 本地 mDNS 广播发现 IP，浏览器直接建立内网 WebSocket 直连。 | 通过 Hub WebSocket 盲中继转发加密密文（基于 Wasm 实现 ChaCha20 客户端解密）。 | 零安装、零配置，任何 PC 或手机浏览器打开即用。 |
| **移动端 App**<br>(iOS / Android) | 扫码配对，同 Wi-Fi 下走局域网广播直接建连。 | 走云端 Hub 盲中继。支持后台挂起无感重连（无 WebRTC 切后台重连迟钝的痛点）。 | 手机切后台不杀进程，耗电极低，随时随地应急运维。 |
| **桌面端 App**<br>(`redash-app`) | 原生 Socket 直连局域网 Agent。 | 走 Hub 盲中继；或配合本机 Tailscale 节点实现跨公网虚拟内网直接直通。 | 极致的原生 120 FPS 渲染，支持全局 HUD 与多窗分屏。 |

## 四、四大核心技术基石

### 1. 真·端到端加密数据信封 (E2EE Envelope)
- **密钥协商**：两端利用已有的 ED25519 密钥派生 X25519，通过 ECDH 交换一次性 Ephemeral 密钥，生成会话对称密钥。
- **密文封包规范**：
  ```rust
  pub struct EncryptedEnvelope {
      pub session_id: String,     // 路由标识（Hub 仅依据此字段转发）
      pub seq_num: u64,           // 序列号（单调递增，防重放）
      pub nonce: [u8; 12],        // 一次性随机数
      pub ciphertext: Vec<u8>,    // ChaCha20 加密后的真实数据
      pub auth_tag: [u8; 16],     // Poly1305 消息认证标签（防篡改）
  }
  ```
- **Hub 角色蜕变**：Hub 变成彻底的“瞎子”，无法提取终端输入的密码或查看返回的代码。

### 2. 局域网 mDNS 就近直连
- `redash-agent` 启动时除了向 Hub 注册，同时在本地监听并在局域网广播 `_redash._tcp.local`。
- 客户端在同网络下发起探测（超时阈值 50ms），探测通则直接建立本地直连，完全不消耗公网流量。

### 3. PTY 会话解耦与断线保活 (Bridge 模式，对标 Orca)
- 将 Agent 底层的 PTY 进程生命周期与网络 WebSocket 彻底解耦。
- 网络闪断或移动端切后台时，**不终止远程 Shell 进程**，终端输出写入本地环形回退缓冲区（Ring Buffer）；
- 网络重连后，客户端带上 `session_id` 和最后的 `seq_num` 重新附加（Re-attach），自动对齐遗漏字符，体验丝滑无感。

### 4. 现场治理交互安全升级
- 针对前述“释放端口误杀 Hub”的问题，**彻底移除硬编码端口**：
  - 点击【释放端口】触发交互浮层，支持自定义端口输入（80, 443, 3000 等）；
  - 增加**防自杀防护机制**：Agent 校验目标端口，若发现是 Agent 自身或 Hub 的控制端口，直接拒绝并给出警告；
  - 修复 Docker Socket 响应的 `Transfer-Encoding: chunked` 分块解码问题。

## 六、方案核心价值总结

1. **安全达标**：彻底消除中心化特权单点风险，实现同行业最高标准的零信任端到端加密（E2EE）；
2. **性能与成本极致**：同局域网零公网流量，跨公网仅消耗几 KB 文本盲中继流量，极小服务器配置即可稳定运行；
3. **架构稳健轻量**：避免了 WebRTC 的复杂沼泽，全端统一、代码轻巧、可维护性与稳定性达到 100%。
